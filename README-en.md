# Speaker Inversion Builder WebUI for Irodori-TTS v3

**[日本語 README](README.md)**

A local WebUI for building Speaker Inversion datasets, transcribing audio, and running training for Irodori-TTS v3 — all from your browser.

![Screenshot](screenshot/screenshot.jpg)

## Features

- Waveform viewer with range deletion and marker-based splitting
- Automatic silence detection for split marker placement
- Per-segment text entry and correction for training data
- Auto-transcription and batch transcription via faster-whisper
- Reload previously built datasets as projects
- Dataset construction for Speaker Inversion (Manifest / latent generation)
- Start training directly from the WebUI
- Training batch script template generation
- Test audio generation using trained speaker embeddings
- UI language switcher (日本語 / English)

## Getting Started

On Windows, run:

```bat
run.bat
```

The WebUI starts at:

```text
http://127.0.0.1:7863
```

To start manually:

```bat
uv sync --no-dev
uv run --no-sync python webui\app.py --host 0.0.0.0 --port 7863
```

## Initial Setup

On first launch, you will be prompted to set the path to your Irodori-TTS v3 folder.

Enter the path in the dialog or the Settings tab, for example:

```text
C:\path\to\Irodori-TTS-v3
```

The **Browse** button opens a folder selection dialog on the machine running the WebUI. If you are accessing from a remote device, the dialog appears on the server side.

## Basic Usage

1. **Data Prep**
   - Upload WAV / MP3 files.
   - Select a range on the waveform.
   - Delete ranges, add markers, run auto marker detection, or split as needed.
   - Previously built datasets can be reloaded as projects.

2. **Segments**
![Segments tab](screenshot/screenshot2.jpg)
   - Enter or correct the read-aloud text for each segment.
   - **Transcribe all segments** runs batch auto-transcription for all segments at once.
   - Manually correct any segments where auto-transcription was blank or inaccurate.
   - Transcription uses faster-whisper CPU inference by default.
   - CUDA inference can be enabled by editing the launch batch file, but requires additional files and a larger venv.

3. **Training**
![Training tab](screenshot/screenshot3.jpg)
   - Click **Build Dataset**.
   - Click **Run Manifest Preparation**.
   - Click **Start Training**.
   - The training log is displayed on the right side of the screen.
   - The final output file is `outputs/checkpoint_final.speaker.safetensors`.  
     (Intermediate checkpoints are also saved. Once satisfied with the result, you may delete all except `checkpoint_final`.)
   - The embedding file extension must be `.speaker.safetensors`.

4. **Test Generation**
![Test generation tab](screenshot/screenshot4.jpg)
   - Select a trained speaker embedding.
   - Enter text and run generation to verify the training result.
   - Embeddings not shown in the list can be specified directly in the **Speaker Embedding path** field.

## Output Files

Main output locations:

```text
data/
  datasets/
    <dataset-name>/
      source.jsonl
      project_state.json
      manifest.jsonl
      latents/
      wavs/
      train.bat
      train.sh
  logs/
  uploads/
  segments/

outputs/
  <dataset-name>/
    checkpoint_final.speaker.safetensors
```

### Trained Speaker Embedding

The primary output file used as a speaker embedding is:

```text
outputs/<dataset-name>/checkpoint_final.speaker.safetensors
```

This `.speaker.safetensors` file is used as the speaker embedding in test generation.

### Dataset

After building a dataset, the working files are created at:

```text
data/datasets/<dataset-name>/
```

Key files:

- `source.jsonl`: Audio paths, text, and speaker info for training
- `project_state.json`: State file for restoring data preparation in the WebUI
- `manifest.jsonl`: Training manifest generated by Manifest Preparation
- `latents/`: Latent files generated by Manifest Preparation
- `wavs/`: Audio files copied for the dataset

### Logs

Logs for Manifest Preparation, training, and test generation are saved at:

```text
data/logs/
```

Refer to these if something is not working as expected.

## train.bat / train.sh

`train.bat` / `train.sh` are sample scripts for re-running training from an existing dataset.

If you train via the WebUI, you do not need to use these directly.

Use cases:

- Re-training on the same dataset without the WebUI
- Reviewing the exact training command
- Manually adjusting parameters before re-running

Generated at:

```text
data/datasets/<dataset-name>/train.bat
data/datasets/<dataset-name>/train.sh
```

These scripts reflect the settings at the time **Build Dataset** was last run. If you change settings and want them applied to the scripts, run **Build Dataset** again.

## Notes

- Irodori-TTS v3 itself is required separately. Older versions that do not support Speaker Inversion will not work.
- If you move the Irodori-TTS v3 folder, update the path in the WebUI Settings tab.
- On some environments, audio decoding may fail. In that case, the DLL files from a full shared FFmpeg build are required. (Only the DLLs are needed — not `ffmpeg.exe`. An essentials build with bundled DLLs will not work.)
- Dataset names containing Japanese characters are supported, but manually running the generated `.bat` may be affected by character encoding or shell environment.
- Tested and working on the developer's machine. Behavior on other environments is not guaranteed.
- This project contains AI-generated content.
